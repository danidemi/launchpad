# idea-capture Skill

Turn whatever the user has (a sentence, a rant, a half-formed pitch) into a
structured idea document. Never invent facts about the business — ask when
something is missing, don't guess and present a guess as fact.

---

## Phase 1 – Elicit the Raw Idea

If the user hasn't already described the idea in this conversation, ask them
to describe it in their own words, in as much or as little detail as they
have. Do not require a polished pitch — capture whatever they give you.

---

## Phase 2 – Structure It

Map what they said onto these fields. Leave a field explicitly marked
`(unclear — ask)` rather than filling it with a plausible-sounding guess.

- **Problem**: what pain, friction, or unmet need does this address? Who
  feels it, and how are they coping today without this?
- **Solution**: what is actually being built/offered/sold?
- **Target customer**: the specific first segment, not "everyone". Prefer a
  concrete persona over a demographic label.
- **Value proposition**: the one sentence that explains why the target
  customer would switch to this over their current alternative.
- **Unfair advantage / differentiation**: why can't this be easily copied?
  (It's fine if the user doesn't know yet — mark it open.)
- **Channels**: how will the target customer find out this exists?
- **Revenue model**: how does money come in? (subscription, one-off,
  marketplace cut, ads, etc.)
- **Key risks / open questions**: the 2-4 assumptions that, if wrong, break
  the idea. Surface these yourself if the user hasn't — this is where you
  add the most value, not by softening or cheerleading the idea.

If 2+ core fields (Problem, Solution, Target customer) are missing or too
vague to act on, ask targeted follow-up questions before writing anything —
one round of questions is enough, don't interrogate.

---

## Phase 3 – Write `idea.md`

Write (or update, preserving anything the user has already refined) a file
named `idea.md` in the current project with the structured fields above as
headed sections. Keep it in the user's own words and framing as much as
possible — this is their idea, not a template filled with generic business
prose.

If `idea.md` already exists, treat this as a refinement pass: show what
changed rather than silently overwriting.

---

## Phase 4 – Hand Off

Tell the user the idea is captured and that `vision-crafting` (vision/mission)
and `business-naming` are natural next steps — but don't run them
automatically; let the user decide what's next.
